# 005: 変動費の導入（Phase 9 Wave 2）

## 背景

specs/004 で「最優先の技術課題」として記録した欠陥への対処。

導入前のこのゲームの費用は 給与・オフィス維持費・支払利息・再採用コスト・一時費用だけで、
**売上に連動する費用が1つも存在しなかった**。帰結は次の4点。

- 限界利益率が常に 100%
- 損益分岐点売上高が固定費合計に退化（本来の `固定費 ÷ 限界利益率` にならない）
- CVP・差額原価・営業レバレッジが構造的に表現できない
- 8つの引き出しのうち実働は3つ

「遊ぶことが経営の学習になる」を掲げる以上、これは看板に関わる欠陥だった。
とくに旧 `breakeven` 問題は **「このゲームの中では正しいが、現実の経営では誤り」** を
教えてしまっていた。

## 設計

### 変動費率は製品の品質に連動する

```
変動費率 = 0.30 + 0.15 × (品質 / 100)   （上限 0.90）
```

| 品質 | 変動費率 | 限界利益率 |
|---|---|---|
| 20 | 33.0% | 67.0% |
| 30（基準） | 34.5% | 65.5% |
| 80 | 42.0% | 58.0% |

物語上は「高機能な製品ほどクラウド費とサポート工数が嵩む」。
ゲーム上は **「売上は伸びるが、1円あたりの儲けは薄くなる」** というトレードオフになる。

これにより品質を上げる判断が一方向の正解でなくなり、**製品構成そのものが意思決定になる**。
全社の限界利益率は「どの製品がどれだけ売れたか」で決まる加重平均として動く。

率は純粋関数 `getVariableCostRate(quality)` で都度導出し、製品には保存しない。
セーブに率が焼き付くと、バランス調整のたびに旧セーブだけ古い率で動き続けるため。

### 難易度は据え置く（売上係数で補正）

変動費をそのまま足すと基準品質の製品で利益が約35%消え、既存プレイヤーの体感が一段難化する。
**構造だけを入れ替え、難易度は動かさない**方針を取り、売上係数を補正した。

```
REVENUE_SCALE_FOR_VARIABLE_COST = 1 / (1 - 0.345) ≈ 1.527
productRevenueBase       50,000 → 76,336
productRevenueMultiplier 10,000 → 15,267
```

補正値は直書きせず、基準変動費率から導出している（`gameConfig.ts`）。

### 計算チェーン

```
売上
 − 変動費            ← Wave 2 で追加。ここまでが限界利益
 − 人件費
 − 支払利息
 − オフィス維持費
 − 再採用コスト
 ＝ 純利益
```

損益分岐点売上高は `固定費合計 ÷ 限界利益率`。**固定費合計そのものより必ず大きくなる。**

## ドリルへの反映

| 問題型 | 変更 |
|---|---|
| `profit` | 変動費を stem と減算チェーンに追加。罠に「限界利益で止まった値」「変動費だけを引き忘れた値」を追加 |
| `breakeven` | **正解を `固定費 ÷ 限界利益率` に修正。** 従来の正解だった「固定費合計」を最も落ちやすい罠に降格 |
| `contributionMargin` | **新規。** 限界利益率を問う。罠は「変動費率（裏返し）」「固定費まで引いた値」「金額そのもの」 |
| `equityRatio` | 変更なし |

引き出し `classification` の trigger を拡張した（貸借の位置だけでなく「売上に連動するか」も
属性識別の対象になったため）。

## UI

- 財務パネル: 変動費 / 限界利益（率つき）/ **損益分岐点売上高** の3行を追加
- 月次決算モーダル: 売上 → 変動費 → 限界利益（率つき）→ 固定費群 の順に表示
- 収支見込み: 変動費の見込みを差し引く（直近決算の実績率を優先、初月のみ品質平均で代用）
- 敗因コメント: 「売上が固定費を上回る前に」→「限界利益が固定費を上回る前に」

資金危険水域の判定には変動費を**含めない**。売上ゼロでも出ていく金＝固定費だけが、
資金が尽きるまでの月数の分母になるため。

## 後方互換

変動費導入前のセーブには `variableCost` が無い。`normalizeGameState()` が 0 で埋める。
変動費 0 ＝ その月の限界利益率 100% であり、導入前の決算をそのまま表現していて事実として正しい。
